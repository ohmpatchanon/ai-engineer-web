## โมเดล AI คือฟังก์ชันคณิตศาสตร์ที่ปรับค่าจากข้อมูล

โมเดล Machine Learning ทุกแบบ สรุปแล้วคือฟังก์ชันคณิตศาสตร์แบบเดียวกัน: รับ input หนึ่งชุด ส่งผ่านการคำนวณครั้งแล้วครั้งเล่า แล้วปล่อย output อีกชุด เช่น รับอักขระ 500 ตัว แล้วยหนึ่งประโยคว่ามีความน่าจะเป็นเท่าไรว่าเป็นภาษาไทย ภาษาอังกฤษ หรือภาษาเวียดนาม ข้อต่างจากโปรแกรมแบบกฎดั้งเดิมคือ โปรแกรมดั้งเดิมผู้เขียนกำหนดทุกเงื่อนไขเอง ส่วนโมเดลปล่อยให้ข้อมูลกำหนดค่าพารามิเตอร์เอง ซึ่งคือตัวเลขย่อย ๆ ภายในฟังก์ชัน
ตัวเลขทุกตัวที่ไหลในระบบเรียกว่า tensor ซึ่งเป็นแค่กล่องตัวเลขหลายมิติ: ตัวเลขตัวเดียวเรียกว่า scalar, รายการตัวเลขหนึ่งแถวเรียกว่า vector, ตารางตัวเลขเรียกว่า matrix และกล่องที่ซ้อนหลายชั้นเรียกว่า tensor สีญญาณทั้งหมดในโมเดลเคลื่อนที่ผ่าน tensor เหล่านี้ และโครงข่ายประสาทเทียมก็คือการคูณ matrix ผูกกับ vector ซ้ำกันหลายร้อยชั้น สลับกับการกระทำทางคณิตศาสตร์ที่บังคับสัญญาณให้เป็นรูปที่ชั้นถัดไปรับได้
สิ่งที่ทำให้ทฤษฎีเหล่านี้ "ใช้จริง" ไม่ใช่การพิสูจน์สูตร แต่คือสัญชาตญาณว่าตัวเลขแต่ละชุดจะไปทางไหนและทำไม เช่น เวลาโมเดลฝังคำ (embedding) ทำไมคำที่ความหมายใกล้กันถึงได้เวกเตอร์ชี้ไปทิศทางใกล้กัน คำตอบคือโครงสร้างคณิตศาสตร์ของพื้นที่ที่เราบังคับให้มันเรียน ไม่ใช่เวทมนตร์ การเห็นคณิตศาสตร์แบบนี้ทำให้เวลาโค้ดแตก คุณมีแบบจำลองในหัวในการไล่งาน มากกว่าการสุ่มเปลี่ยนค่าแล้วหวังว่าจะดีขึ้น
ด้านที่ต้องระวังคือ อย่าคิดว่าต้องท่องสูตรทุกอย่างก่อนเริ่มลงมือ คณิตศาสตร์ 80% ที่ใช้จริงมีแค่อันเดียวคือ linear algebra บวกลบค่า อนุพันธ์เพื่อหาทิศทาง และความน่าจะเป็นเพื่อวัดความไม่แน่นอน ส่วนที่เหลือเป็นการรวมกันของสิ่งเหล่านี้ในสูตรที่ดูใหญ่และน่ากลัวเท่านั้น ถ้าเข้าใจแก่นสามอย่างนี้ ดูสูตรอะไรก็จะค่อย ๆ อ่านออกทีละขั้น ไม่ใช่เห็นแต่สัญลักษณ์
มุมมอง trade-off ตั้งแต่ต้นคือ ความคณิตศาสตร์ช่วยให้โมเดลเรียนรู้จากข้อมูลได้อย่างยืดหยุ่น แต่ก็แลกกับความที่โมเดลไม่จำเป็นต้อง "เข้าใจแบบมนุษย์" มันรู้แค่การจัดวางตัวเลขให้ผลลัพธ์บนข้อมูลฝึกดีขึ้นเท่านั้น ข้อจำกัดนี้คือรากของปัญหา overfitting และการตีความไม่ได้ ซึ่งเป็นเรื่องที่บทเรียนเรื่องการเรียนรู้และเรื่องการวัดผลจะขยายต่อ
**ตัวอย่าง — อุปมา: เครื่องขยายเสียงที่จูนเองได้**

ลองนึกว่าโมเดลคือแอมพลิฟายเออร์ที่รับเสียงหนึ่งอย่าง แล้วปรับปุ่มเกน บาลานซ์ และอีควอไลเซอร์ให้เข้ากับเพลงแต่ละเพลง ปุ่มเหล่านั้นคือพารามิเตอร์ ฟังก์ชันคณิตศาสตร์คือวงจรขยายเสียง และข้อมูลฝึกคือเพลงมากมายที่เราให้มันฟังเพื่อเริ่มจูน — แต่จูนเก่งในห้องทดลองไม่ได้แปลว่าจะฟังเพราะทุกเครื่อง

## เวกเตอร์: จุดข้อมูลแต่ละตัวคือจุดในปริภูมิหลายมิติ

เวกเตอร์คือรายการตัวเลขเรียงลำดับ เช่น น้ำหนัก ส่วนสูง อายุ ของคนหนึ่งคน รวมเป็นเวกเตอร์ [72, 175, 29] ข้อมูลหนึ่งแถวกลายเป็นเวกเตอร์หนึ่งชุด และแต่ละมิติคือ feature เดียว โมเดลไม่ได้ "อ่าน" ตารางเหมือนคน แต่เห็นแต่ละตัวอย่างเป็นจุดเดียวในพื้นที่หลายมิติ การจัดกลุ่มที่โมเดลสร้างขึ้นคือการย้ายจุดเหล่านี้ให้อยู่ห่างจากกันหรือใกล้กันตามที่เหมาะสม
ขนาดของเวกเตอร์ (norm) บอกว่าจุดนั้นอยู่ไกลจากจุดศูนย์กลางแค่ไหน และทิศทางของเวกเตอร์บอกว่ามันชี้ไปทางไหน เวลาเราพูดว่า "สองคำมีความหมายใกล้กัน" ในโลกของ embedding หมายความว่าเวกเตอร์สองตัวชี้ไปทิศทางที่ใกล้กัน ไม่ได้แปลว่าค่ามันเท่ากันซะทั้งหมด การวัดทิศทางนี่คือหัวใจของการค้นจากความหมายทั้งหมด
การดำเนินการพื้นฐานที่เจอตลอดคือ dot product นำสมาชิกตำแหน่งเดียวกันคูณกันแล้วรวมผล เป็นวิธีวัดความคล้ายและเป็นแกนหลักของ attention, embedding search และ linear layer ทั้งหมด ถ้าคุณเข้าใจ dot product คุณเข้าใจครึ่งของ Transformer แล้ว เพราะใน attention โมเดลก็เปรียบเทียบเวกเตอร์ของคำทุกคู่ด้วยวิธีนี้ เช่นกันว่า "คำนี้ควรสนใจคำไหนเป็นพิเศษ"
จุดที่ต้องแยกให้ชัดคือ dot product สับสนกับระยะทางยูคลิด (Euclidean distance) เพราะ dot product สูงไม่ได้แปลว่าจุดใกล้กันที่สุดเสมอไป มันคำนึงถึงทิศทางเป็นหลัก แต่ระยะทางคำนึงถึงตำแหน่งจริง นั่นคือเหตุผลว่าทำไม cosine similarity (เอา dot product หารด้วยขนาดของเวกเตอร์ทั้งสอง) จึงถูกใช้บ่อยเมื่อเราแคร์ทิศทางแต่ไม่แคร์ขนาด เช่นการค้นประโยคที่ความหมายคล้ายกันโดยไม่ถือสาเรื่องความยาว
trade-off ที่ควรเห็นคือ เวกเตอร์มิติสูงสื่อสารความหมายได้ละเอียด แต่ก็เป็นปัญหาเพราะ "สาปของมิติ" (curse of dimensionality) ทำให้ระยะห่างระหว่างจุดเริ่มไม่น่าเชื่อถือ เมื่อมิติสูงขึ้นเรื่อย ๆ จุดทุกตัวจะดูเหมือนอยู่ไกลพอ ๆ กัน โชคดีที่โมเดลลึกสมัยใหม่ฝึกให้พื้นที่ที่ต้องใช้จริงอ่อนแอลงด้วยการเรียนรู้การวางตำแหน่ง ไม่ใช่การห่มองห่างเท่าเดิมในทุกมิติ
### สูตร: Dot product, norm และ cosine similarity

a · b = Σ (aᵢ × bᵢ)   |   norm(a) = √(Σ aᵢ²)   |   cosine = (a · b) / (|a| × |b|)

> a · b สูงแปลว่าชี้ไปทิศเดียวกันมาก ส่วน cosine อยู่ระหว่าง -1 ถึง 1 ค่าใกล้ 1 แปลว่าชี้ทิศเดียวกันเกือบเป๊ะ ใกล้ -1 แปลว่าชี้ตรงข้าม — ใช้เทียบความคล้ายของ embedding โดยตัดผลของขนาดออก
```python
import numpy as np

king = np.array([0.8, 0.2, 0.9])
queen = np.array([0.7, 0.3, 0.8])
man = np.array([0.1, 0.9, 0.2])

dot = np.dot(king, queen)          # วัดความสอดคล้องของทิศ
cos = dot / (np.linalg.norm(king) * np.linalg.norm(queen))
print('dot:', dot, 'cosine:', cos)  # king-queen ได้ cosine สูงกว่า king-man
```
![Two vectors a and b from the same origin with angle theta; cosine equals dot product over norms and equals cos(theta)](/diagrams/vector-space.svg)

*Vector space and cosine similarity — มุม θ ระหว่างเวกเตอร์สองตัวคือความคล้าย: cos = 1 ชี้ทิศเดียวกัน, 0 ตั้งฉาก, −1 ชี้ตรงข้าม — normalize แล้ว cosine คือแค่ dot product ของเวกเตอร์หนึ่งหน่วย*

## เมทริกซ์: ชั้นของโมเดลคือตารางคูณหลายมิติพร้อมกัน

ค่า weight ของ linear layer หนึ่งในโครงข่ายประสาทคือเมทริกซ์ เป็นตารางตัวเลขที่บอกว่า input ระดับไหน ควรมีอิทธิพลกับ output ระดับไหนเท่าไร การคูณเมทริกซ์กับเวกเตอร์คือการส่งสัญญาณจากชั้นหนึ่งไปยังชั้นถัดไป พร้อมถ่วงน้ำหนักใหม่ทุกมิติ ถ้า input มี 768 มิติและ output ต้องการ 768 มิติ เราจะมีเมทริกซ์น้ำหนักขนาด 768 คูณ 768 ซึ่งก็คือตัวเลขประมาณ 590,000 ค่าในชั้นเดียวที่ต้องเรียนรู้
ประโยชน์สำคัญของการมองเป็นเมทริกซ์คือ อ่าน shape ของ tensor ออกทันที รูปทรงบอกเลยว่าข้อมูลเป็น batch ขนาดเท่าไร แต่ละตัวอย่างกี่มิติ และโมเดลจะปรับค่าพารามิเตอร์เท่าไร เวลาโมเดลรายงานว่า "shape mismatch" หมายความว่ารูปทรงสองฝั่งคูณกันไม่ได้ เช่น เอาเวกเตอร์ 512 มิติไปคูณเมทริกซ์ที่สร้างไว้สำหรับ 768 มิติ โมเดลไม่ได้บั๊กแบบสุ่ม มันกำลังบอกว่าหลักการของ linear algebra กำลังทำงาน และคุณป้อนรูปทรงผิด
การคูณเมทริกซ์เป็นแบบขนาน (parallel) ได้ยอดเยี่ยมบน GPU เพราะการคูณแต่ละแถวไม่ขึ้นกับแถวอื่น นั่นคือเหตุผลลึกข้อหนึ่งว่า deep learning เทรนได้เร็วในฮาร์ดแวร์สมัยใหม่ เพราะทฤษฎีทั้งหมดถูกออกแบบเป็น matrix operation ตั้งแต่แรก ไม่ใช่วางยาวเป็นเส้นตรงแบบโปรแกรมภาษาซี
แต่ต้องระวังเรื่องตำแหน่งที่เมทริกซ์ซ่อนพิษคือ overparameterization หรือพารามิเตอร์เยอะเกินข้อมูล เช่น มีพารามิเตอร์หลายล้านตัวแต่ข้อมูลฝึกมีแค่ไม่กี่หมื่นตัวอย่าง โมเดลก็มีความสามารถมากพอที่จะ "จำ" คำตอบแทนที่จะเรียนรู้รูปแบบทั่วไป ซึ่งดูจากรูปทรงของเมทริกซ์แล้วอธิบายได้ชัดกว่าคำพูด น้ำหนักเยอะเกินไปเมื่อเทียบกับความหลากหลายของข้อมูล จะทำให้โมเดลไหวไปตามเสียงรบกวน
คำถามที่ควรฝึกถามตัวเองทุกครั้งที่เห็นชั้นใหม่คือ shape สองฝั่งตรงกันไหม แล้วขนาดของมิติมีเหตุผลอะไร เช่น เพิ่ม hidden dimension เป็น 2 เท่าไม่ได้หมายความว่าดีขึ้นเสมอ เพราะมันเพิ่มค่าคำนวณและพารามิเตอร์แบบกำลังสอง ขนาดที่เหมาะสมมักเป็นค่าที่ต้องลองแล้ววัดผลบนข้อมูล validation ไม่ใช่การเดาจากชื่อสถาปัตยกรรม
```python
# batch 32 ตัวอย่าง, แต่ละตัวมี 768 มิติ -> เอาไปผ่าน linear layer เหลือ 512 มิติ
import numpy as np

x = np.random.randn(32, 768)   # shape (32, 768)
W = np.random.randn(768, 512)  # shape (768, 512)
y = x @ W                      # @ คือ matmul, ได้ shape (32, 512)
print(y.shape)                 # (32, 512)

# ถ้า W มี shape (256, 512) จะ error ทันที เพราะมิติที่ชิดกันต้องตรงกัน (768 != 256)
```

## โมเดลเป็นฟังก์ชัน: activation และชั้นที่ไม่เป็นเส้นตรง

ถ้ามีแต่การคูณเมทริกซ์หลายครั้งติดกัน จะรวมเป็นเส้นตรงเส้นเดียว ไม่ว่าเราจะวางกี่ชั้นก็ตาม การมีเพียง linear layer ซ้อนกันไม่มีพลังเพิ่มขึ้นเลยเพราะฟังก์ชันเส้นตรงบวกกันก็ยังเป็นเส้นตรง ปริมาณงานนี้ทำให้โครงข่ายประสาทเทียมมีพลังมากกว่าการเรียนรู้เส้นตรงได้ คือหน้าที่ของ activation function ที่แทรกหลังการคูณทุกชั้น
activation แบบที่พบบ่อยที่สุดคือ ReLU ซึ่งเปลี่ยนทุกค่าลบให้เป็นศูนย์ และคงค่าบวกไว้ เป็นฟังก์ชันที่เข้าใจง่าย เร็ว และทำงานได้ดีในงานส่วนใหญ่ พูดภาษาง่ายคือ ReLU บอกว่า "สัญญาณนี้แรงพอให้ผ่านไหม" ถ้าต่ำกว่าศูนย์ให้ตัดทิ้งทันที ถ้าสูงกว่านั้นก็ส่งไปต่อเต็มค่า เทคนิคนี้เรียบง่ายเพียงพอแต่มีข้อเสียคือ neuron ที่ตายไปแล้ว (dead neuron) จะไม่มีทางกลับมามีชีวิตเป็นปกติได้หากสัญญาณลบเสมอ
ฟังก์ชันอื่นอย่าง sigmoid และ tanh ใช้บีบสัญญาณให้อยู่ในช่วง 0-1 หรือ -1 ถึง 1 ซึ่งดีสำหรับ output ที่ต้องการความน่าจะเป็นหรือค่าที่จำกัด แต่เสียเปรียบตรงที่พอค่านอกช่วงนั้นจะอิ่มตัว (saturation) และ gradient จ่อลงไปใกล้ศูนย์ ทำให้นฝึกช้าในหลายชั้น ข้อจำกัดนี้คือเหตุผลว่าทำไม ReLU จึงกลายเป็นค่าตั้งต้นในชั้นซ่อน และ sigmoid จึงมักเหลือใช้แค่ปลายสุดของโมเดลเฉพาะทาง
อีกเครื่องมือสำคัญคือ softmax ซึ่งเปลี่ยนเวกเตอร์คะแนนดิบให้เป็นความน่าจะเป็นที่รวมกันเป็น 1 พูดอีกแบบคือ softmax เอาความต่างของคะแนนมาขยายให้ชัด เช่น คะแนน [2, 1, 0.1] จะกลายเป็นความน่าจะเป็นประมาณ [0.66, 0.24, 0.11] ที่คะแนนของคำตอบนำโด่งเห็นชัด ความน่าจะเป็นนี้ใช้แทนความมั่นใจของโมเดลในแต่ละคลาส และเป็นตัวเชื่อมต่อไปยัง loss แบบ cross-entropy (ฟังก์ชันต้นทุนทางสถิติแบบหนึ่ง)
trade-off ของ activation และสถาปัตยกรรมคือ ความไม่เป็นเส้นตรงทำให้โมเดลเรียนรู้รูปแบบซับซ้อนได้ แต่ก็ทำให้การปรับตั้งทำได้ยากขึ้นเพราะต้องมีขั้นตอนเทรนที่ถูกต้อง การเพิ่มชั้นและฟังก์ชันแปลก ๆ โดยไม่รู้เหตุผล มักทำให้เทรนไม่ลงก่อนจะทำให้แม่นขึ้น การเข้าใจว่าชั้นนั้นทำอะไรกับสัญญาณคือกุญแจในการอ่านโมเดลจริง ไม่ใช่การท่องชื่อสถาปัตยกรรมให้ได้
### สูตร: Activation ฟังก์ชันหลัก

ReLU(x) = max(0, x)   |   sigmoid(x) = 1 / (1 + e⁻ˣ)   |   Softmax(xᵢ) = eˣⁱ / Σ eˣʲ

> ReLU ตัดลบเป็น 0 ไว้ใช้ในชั้นซ่อน, sigmoid บีบเป็น 0-1 ไว้ใช้เฉพาะทาง, softmax แปลงคะแนนหลายคลาสเป็นความน่าจะเป็นรวมได้ 1 — ค่า e ˣ หมายถึงเลขชี้กำลังที่ทำให้ค่าต่างขยายตัว

## แคลคูลัส: derivative, gradient และที่มาของ chain rule

โมเดลถูกวัดด้วยฟังก์ชัน loss ที่บอกว่า "ตอนนี้ผิดแค่ไหน" และงานของ training คือลดค่านี้ derivative คือเครื่องมือบอกว่า "ถ้าฉันเพิ่ม input ตัวนี้อีกนิด loss จะเปลี่ยนไปทางไหนเท่าไร" เช่น ถ้าเพิ่มตัวเลขนี้ 1 หน่วยแล้ว loss ลด 2 หน่วย derivative จะประมาณ -2 หมายความว่าเพิ่มค่าต่อมีประโยชน์ ถ้า derivative เป็น +3 หมายความว่าเพิ่มค่าจะยิ่งทำให้ loss พุ่ง แสดงว่าตัวนี้พาโมเดลผิดทาง
แต่โมเดลมีพารามิเตอร์นับล้านตัว ไม่ใช่ตัวเดียว gradient คือรายการ derivative ของ loss เทียบกับพารามิเตอร์ทุกตัวพร้อมกัน เป็นเวกเตอร์ที่ชี้ไปทางที่ loss เพิ่มเร็วที่สุด และจุดที่มันชี้สำคัญสี่อย่าง: ทิศทางที่ควรเดิน (ฝั่งตรงข้าม gradient) และขนาดของความชันที่คุณต้องรู้ก่อนใช้ ขั้นตอน gradient descent คือคำนวณ gradient แล้วก้าวไปทิศตรงข้ามด้วยขนาดที่กำหนดโดย learning rate
chain rule คือเครื่องมือคำนวณ gradient ผ่านหลายชั้น เพราะ loss ขึ้นกับ output ที่ขึ้นกับชั้นก่อน ๆ ทุกชั้นติดเป็นลูกโซ่ในคำนวณ ปัญหาที่เกิดตอนลูกโซ่ยาวคือค่าที่คูณต่อกันอาจค่อย ๆ เล็กลงจนหายไป (vanishing gradient) หรือระเบิดจนพุ่ง (exploding gradient) นี่คือเหตุผลเชิงคณิตศาสตร์ว่าทำไม deep network ที่เก่าจึงเทรนไม่ลง และเทคนิคอย่าง residual connection หรือ normalization ถูกออกแบบมาแก้ precisely ที่ chain rule อันนี้
learning rate คือขนาดก้าวที่ไม่ใช่ทิศทาง ถ้าใหญ่เกินจะ "กระโดดข้าม" หุบเขาของ loss ไปเลยและวนรอบไม่ลง ถ้าเล็กเกินจะคืบช้าจนเทรนไม่ทัน ส่วน momentum และ Adam คือวิธีแก้ก้าวเล็ก/สั่นด้วยการจดทิศทางก้าวก่อน ๆ ไว้แล้วรู้สึกว่ามักจะไปถูกทางเดียวกัน Adam ค์เอา gradient มาหารด้วยค่าเฉลี่ยของขนาด gradient เพื่อให้พารามิเตอร์ช้า/เร็วในทุกมิติเป็นจังหวะเดียวกัน เป็น optimizer มาตรฐานของ deep learning มากมายเพราะไม่ตั้งเป๊ะกับค่าว่าแต่ละมิติแรงไม่เท่ากัน
อุปมาที่ใช้บ่อยที่สุดคือการเดินลงภูเขาในความมืด ต้องใช้เท้าสัมผัสความชันของทาง (gradient) แล้วก้าวไปทางที่ลาดลง (learning rate) ก้าวใหญ่เกิน = ไถลข้ามหุบเขาลงไปอีกฝั่งแล้วต้องปีนกลับ ก้าวเล็กเกิน = ใช้เวลานานโดยที่อาจหลงทางเพราะไม่เห็นทางลาดชัดพอ ความลาดของภูเขานี้ไม่ใช่ความเสมอกันในทุกจุด โมเดลอาจติดอยู่ที่ที่ราบได้ด้วย เช่น โมเดลติดอยู่ใน saddle point ที่ gradient ใกล้ศูนย์แต่ยังไม่ใช่จุดที่ loss น้อยที่สุด
- ขั้นตอน gradient descent ทีละขั้น: (1) รับตัวอย่างหนึ่งชุด, (2) คำนวณค่าประมาณ (forward), (3) เทียบกับคำตอบจริงหา loss, (4) ถอยหลังหาว่า parameter ตัวไหนควรขยับไปทางไหนเท่าไร (backprop), (5) ลด loss ด้วยการขยับตาม gradient
- learning rate คือขนาดก้าว ไม่ใช่ทิศทาง ใช้กำหนดว่า "จะไวต่อการเปลี่ยนแปลงแค่ไหน"
- momentum คือแรงเฉื่อยในการก้าว ส่วน Adam คือปรับจังหวะก้าวตามมิติ — อย่าคิดว่าต้องไปปรับด้วยมือทุกตัว
- vanishing กับ exploding gradient คือสองปลายของ chain rule ยาวเกินไป ต้องใช้เทคนิคสถาปัตยกรรมช่วย
### สูตร: สูตรที่ขับเคลื่อนการเทรนทั้งหมด

θ ← θ − η · ∇loss(θ)   (θ = พารามิเตอร์, η = learning rate, ∇loss = gradient)

> ทุกขั้นตอนเทรนทำแค่อันเดียว: ขยับพารามิเตอร์ไปทิศตรงข้าม gradient ด้วยขนาดก้าว η — ทำซ้ำจน loss บรรจบ (converge)
> [!STOP: อย่าเอา derivative มาปนกับ movement]
> gradient บอกแค่ "ทางไหนชันที่สุด" ไม่ได้บอกว่าควรก้าวแค่ไหนเสมอไป เปลี่ยน learning rate อย่างเดียวสามารถทำให้เทรนล้มได้ก่อนที่จะได้เริ่มโทษข้อมูลหรือสถาปัตยกรรม

## ความน่าจะเป็น: ภาษาของความไม่แน่นอนและ Bayes

ความน่าจะเป็นไม่ได้หมายความว่า "สุ่มทุกอย่าง" แต่หมายความว่าเราต้องตัดสินใจภายใต้ความไม่แน่นอน เช่น จำแนกเมลเป็น spam หรือไม่ใช่ ทั้งที่มนุษย์ยังไม่แน่ใจกับเมลบางฉบับ โมเดลต้องตอบเป็นความน่าจะเป็นและเลือกคำตอบที่โอกาสสูงสุด ความน่าจะเป็นนี้คือพื้นฐานของ loss หลายแบบใน ML และตัวเลขที่ใช้ตัดสินใจในงานจริง ไม่ใช่แค่เครื่องหมายที่บอกว่ามั่นใจแต่คือตัวเลขที่ตีความได้
distribution คือ "รูปแบบการกระจาย" ของข้อมูล เช่น สูงของคนส่วนใหญ่กระจายเป็นเส้นโค้ง bell curve แบบ normal distribution โดยที่ค่าเฉลี่ยอยู่ตรงกลาง ค่าที่ห่างจากค่าเฉลี่ยจะเกิดได้น้อยลง การรู้ distribution ช่วยให้รู้ว่าแบบจำลองไหนเหมาะ เช่น หากข้อมูลขาว outlier มากอาจต้องดัดแปลงด้วย log หรือใช้โมเดลที่ทนทาน และความแปรปรวน (variance) บอกความกระจายกว้างแค่ไหน
Bayes theorem คือหัวใจที่เชื่อม prior (ความเชื่อก่อนเห็นข้อมูล) กับ posterior (ความเชื่อหลังเห็นข้อมูล): P(A|B) = P(B|A) × P(A) / P(B) พูดง่าย ๆ คือความน่าจะเป็นที่ A เป็นจริงเมื่อเห็น B ขึ้นอยู่กับว่า B เกิดขึ้นพร้อม A บ่อยแค่ไหน (|เท่า|e) และความน่าจะเป็นของ A ก่อนเห็นอะไรเลยเป็นแค่ไหน โมเดล Bayes แต่ละตัวและการอัปเดตความมั่นใจในเชิงสถิติ ล้วนอาศัยหลักการเดียวกัน
expectation คือค่าเฉลี่ยถ่วงน้ำหนักตามความน่าจะเป็น ส่วน variance คือค่าคาดหวังของกำลังสองของความเบี่ยงเบนจากค่าเฉลี่ย สองตัวนี้สรุปข้อมูลทั้งหมดเป็นตัวเลขสั้น ๆ และอยู่ในสูตร loss ต่าง ๆ เช่น MSE มาจากการเฉลี่ยกำลังสองของความผิดที่เกิดขึ้นโดยคาดหวังจากข้อมูล (expected squared error) การเข้าใจ expectation ทำให้มอง loss เป็น "ความผิดพลาดที่คาดหวัง" ไม่ใช่แค่ตัวเลขที่ดวงไฟขึ้นแล้ว
trade-off ที่ต้องเข้าใจคือ โมเดล probabilistic (เช่น logistic regression) ให้ความไม่แน่นอนออกมาเป็นความน่าจะเป็นและแปลผลได้ แต่บางงานต้องการคำตอบเดียวที่ชัดเจน การบังคับให้เป็น 0/1 อาจอ่านง่ายแต่ไม่มี informative robustness ฝั่งกลับกัน โมเดลที่ตารางการตัดสินใจแบบ deterministic อาจเทรนง่ายกว่าแต่ซ่อนความไม่แน่นอน งานบางอย่างยอมจ่ายค่าเพื่อความโปร่งใส ส่วนงานอื่นให้ priority กับความแม่นยำโดยตรง
### สูตร: Bayes theorem และ expectation

P(A|B) = P(B|A) × P(A) / P(B)   |   E[X] = Σ x × P(x)

> P(A|B) คือความน่าจะเป็นของ A เมื่อเห็น B, P(A) คือ prior, P(B|A) คือหลักฐานที่พบเมื่อ A จริง, E[X] คือค่าเฉลี่ยถ่วงน้ำหนักของทุกค่าที่เป็นไปได้

## สถิติสำหรับ ML: sample, estimator และ bias-variance

ML ไม่ได้เรียนจาก "โลกทั้งหมด" แต่จากตัวอย่างที่เก็บมา (sample) ตัวอย่างที่เก็บได้คือการประมาณของประชากรเป้าหมาย estimator ใดก็ตาม (เช่น ค่าเฉลี่ยของตัวอย่าง) จะมีทั้ง bias (แนวโน้มผิดแบบเป็นระบบ) และ variance (แก้มแก้มเปลี่ยนไปตามตัวอย่างที่ได้) สองอย่างนี้จะแยกออกจากกันไม่ได้บางครั้งและอยู่รวมกันเป็น "ความผิดพลาดรวม" ซึ่งในบทเรียนเรื่อง how-models-learn จะอธิบายแบบเต็มต่อจากนี้
ตัวอย่างคลาสสิกของ sampling bias คือเก็บข้อมูลจากโซเชียลมีเดียอายุน้อยเป็นส่วนใหญ่ แล้วเทรนโมเดลเพื่อทำนายความต้องการของประชากรทั่วไป โมเดลจะแม่นที่ "ข้อมูล" แต่หลงทางในโลกจริงเพราะตัวอย่างไม่เป็นตัวแทน จำนวนข้อมูลไม่ใช่แค่ปริมาณ แต่คือความสามารถเป็นตัวแทนของประชากรที่ต้องทำนายวันจริงขอเสนออย่างจริงใจว่า โมเดลเก่งในข้อมูลฝึกเพียงอย่างเดียวไม่ได้เลยถ้า sample bias ไม่ถูกจัดการตั้งแต่ตอนวางแผนเก็บข้อมูล
inferential statistics มีที่มาจาก sampling คือการอนุมานจากตัวอย่าง โมเดลที่เรียนจากตัวอย่างค่อย ๆ เพิ่มความน่าจะเป็นให้กับคำตอบที่ถูก (maximum likelihood) และตอนใช้งานก็คายความน่าจะเป็นออกมาเป็นคะแนน การเพิ่มความน่าจะเป็นของคำตอบที่ถูกคือหัวใจของการทำนายที่แม่นที่สุด และเอาไปแปลงเป็น loss ได้ เช่น cross-entropy คือการวัดความผิดพลาดจากการจ่ายความน่าจะเป็นผิด ๆ ในคำตอบถูก
confidence interval คือช่วงที่บอกว่า "ค่าจริงมีโอกาสอยู่ในช่วงนี้แบบสมเหตุสมผล" เป็นเครื่องมือที่บังคับให้เรายอมรับความไม่แน่นอนพอดีมากขึ้นกว่าการรายงานตัวเลขอย่างเดียว ในงาน ML มันเป็นจุดที่หลายทีมลืม ไม่รายงานว่า validation accuracy 90% นั้นมาจากตัวอย่างกี่ตัวอย่าง และ error bar ใหญ่แค่ไหน โมเดลที่ accuracy 90% จาก 100 ตัวอย่างไม่ได้เชื่อถือเท่า 90% จาก 10,000 ตัวอย่าง
ด้านที่ต้องชั่งน้ำหนักคือ สถิติช่วยให้ประเมินโมเดลอย่างซื่อสัตย์มากขึ้นและการตัดสินใจเชิงความเสี่ยงทำได้ดีกว่า แต่ก็มีข้อเสียคือ ถ้าต้องไปนั่งคำนวณทุกอย่างให้อยู่ในรูปแบบสถิติที่สมบูรณ์ งานอาจช้าและไปช้าสู่การลงมือ ปฏิบัติที่ดีคือให้สถิติเป็นเข็มทิศตัดสินใจงานสำคัญ เช่น เมื่อเลือก metric หรือประเมินว่าการเปลี่ยนโมเดลดีกว่าจริงแค่ไหน ไม่ใช่ทันชีทตั้งแต่สิ่งเล็ก ๆ ทุกจุด
> [!TAKEAWAY]
> หลัก 80/20 ของคณิตศาสตร์ AI คือ dot product (ความคล้าย), gradient (ทิศทางปรับ), และความน่าจะเป็น (การตัดสินใจภายใต้ความไม่แน่นอน) — ส่วนที่เหลือเป็นส่วนขยายของสามอย่างนี้ และสถิติคือสะพานที่ทำให้ตัวเลขเหล่านั้นเชื่อถือได้ในโลกจริง

## ลำดับการอ่านและการฝึกวินัยคณิตศาสตร์เพื่อ debug โมเดลจริง

อย่าเริ่มด้วย linear algebra เต็มตำรา แต่เริ่มจากเวกเตอร์และ dot product ก่อน เพราะใช้ในการค้นและ attention ต่อด้วย gradient และ learning rate เพราะเป็นหัวใจของการเทรน แล้วความน่าจะเป็นพื้นฐาน (distribution, expectation, conditional) เพราะใช้ใน loss และการเลือก metric เมื่อถึง deep learning ค่อยศึกษา matrix shape และ tensor ดูจากรูปของโค้ดจริงจะเข้าใจกว่า
วินัยการฝึกที่ดีคือ อ่านสูตรแล้วแปลออกเป็นคำพูดก่อนท่องสัญลักษณ์ ทุกครั้งที่เห็นสูตรถามตัวเองสามคำถาม: ตัวแปรนี้คืออะไร, ถ้าตัวแปรนี้ใหญ่กว่าจะเกิดอะไรขึ้น, และตัวเลขนี้ใช้ตัดสินใจตรงไหนในงานจริง ถ้าตอบสามคำถามนี้ได้ คุณเข้าใจสูตรนั้นไม่ได้จำมัน
ส่วนที่คนเริ่มต้นลืมคือ คณิตศาสตร์เพียงอย่างเดียวไม่พอให้โมเดลเทรนได้ เพราะข้อมูลที่ป้อนให้ต้องผ่านการแปลง feature ที่สอดคล้องกับสมมติฐานของคณิตศาสตร์ ข้อมูลขนาดใหญ่แต่ scale ไม่ถูกต้อง เดี๋ยวตัวเลขคอลัมน์หนึ่งจะกลบตัวเลขอื่นและการไหลของ gradient แต่ละมิติจะเสียสมดุล การเตรียมข้อมูลจึงเป็นส่วนหนึ่งของคณิตศาสตร์ ไม่ใช่ส่วนที่แยกกัน
แนวทางที่แนะนำคือ ผูกสมการแต่ละอันเข้ากับโค้ดอ่านออกทุกครั้ง เช่น สูตร dot product ผูกกับบรรทัดคำนวณ embedding, สูตร gradient ผูกกับขั้นตอนเทรน และสูตร Bayes ผูกกับงานตัดสินใจภายใต้ความไม่แน่นอน วินัยแบบนี้นั้นทำให้เวลาต้อง debug กราฟเทรนหรืออ่าน paper คุณไปที่เส้นเชื่อมเชิงเหตุผลได้เร็ว ด้วยการไล่จาก output ย้อนกลับไปว่าพารามิเตอร์ไหนควรเปลี่ยนและเพราะอะไร
บทต่อไป (เรื่อง how models learn) จะเอาคณิตศาสตร์พวกนี้มาต่อเป็นวงจรเทรนครบรูปแบบ: loss, backward และ update จะเห็นว่าสูตรที่เรียนที่นี่ทำงานรวมกันอย่างไร และทำไมโมเดลจึง overfit ได้ด้วยเหตุผลเชิงคณิตศาสตร์ที่ลึกกว่า "ข้อมูลน้อย" อย่าอ่านคณิตศาสตร์เป็นทฤษฎีแยก แต่เก็บไว้ใช้เป็นเครื่องมือตลอดทางของหลักสูตร
**ตัวอย่าง — Sanity check ก่อน coding ทุกครั้ง**

ก่อนรันเทรนใหญ่ ให้ถาม: (1) shape ของ tensor ทั้งหมดตรงกันไหม, (2) loss เริ่มต้นสมเหตุสมผลไหม (เช่น classification เริ่มต้นควรได้ loss ใกล้ค่า log ของจำนวนคลาส), (3) gradient มี NaN หรือไม่, (4) ค่าคะแนนขาออกอยู่ช่วงไหน (เช่น softmax รวมได้ 1 ไหม) — แค่ 4 คำถามนี้ดักบั๊กได้มากมายก่อนเสียเวลารอ GPU หลายชั่วโมง

## โมเดลรู้เพียง "ยังไงต่อ"

โมเดลภาษาแบบ decoder-only ถูกฝึกด้วย next-token prediction คือให้ข้อความนำหน้าทั้งหมดแล้วฝึกให้ความน่าจะเป็นของ token ถัดไปสูงที่สุด นี่คือหัวใจของการออกแบบโมเดลที่ทำให้ระบบตอบข้อความออกมาได้อย่างต่อเนื่องและสมบูรณ์ ปัจจัยนี้ผลักให้โมเดลเรียนรู้รูปแบบของภาษาและสารบัญที่ถูกต้องขณะที่เทรน
โมเดลไม่ได้รู้ว่ามันกำลังตอบถูกในแง่โลกความจริงหรือไม่ แต่แค่ตอบว่า token ใดเป็นตัวต่อที่ถูกต้องในแง่รูปแบบที่เคยเห็น นั่นทำให้เห็นได้ว่าทำไมบางครั้งโมเดลตอบอย่างมั่นใจแต่ผิดทั้ง ๆ ที่เสียงตอบดูเป็นธรรมชาติอย่างยิ่ง ซึ่งเป็นข้อจำกัดพื้นฐานจากการฝึกที่ไม่ได้มี ground truth ในระบบ
การคิดว่าโมเดลรู้ความจริงเป็นความเข้าใจผิดและทำให้เรามองข้ามความสำคัญของการตรวจสอบข้อมูลภายนอก สำหรับงานที่ความผิดพลาดมีต้นทุนสูงเราต้องมีระบบตรวจสอบและยืนยันเสมอ ก่อนยอมรับคำตอบของโมเดลว่าเป็นความจริง และสิ่งนี้เกี่ยวเนื่องโดยตรงกับความสำคัญของ RAG และ tooling
> [!KEY]
> ถามว่า "รู้ไหม" กับ "ตรวจได้ไหม" — โมเดลแค่ทำนายต่อ ไม่มี ground truth ในหัว จึงต้องมี source/verification ภายนอกเสมอสำหรับงานที่ผิดพลาดแพง

## จากคะแนนสู่คำตอบ: sampling และ temperature

โมเดลคำนวณ logit ให้ทุก token ในชุด vocab จากนั้น softmax เปลี่ยนให้เป็นความน่าจะเป็น แล้วเลือกผลลัพธ์ที่แสดงออกไป การเลือก greedy คือการเลือก token ที่ความน่าจะเป็นสูงสุดซึ่งให้ผลลัพธ์ที่เสถียรที่สุด แต่ทำให้ข้อความซ้ำและแข็งทื่อในบางหน้าที่
Sampling ใช้ temperature ที่ปรับรูปการกระจายความน่าจะเป็นซึ่งสามารถคิดได้เป็นอุณหภูมิของระบบ ถ้าค่า temperature ต่ำจะให้ logit หัวแหลมและสุ่มน้อยลง ถ้าค่าสูงจะให้ logit แบนและสุ่มมากขึ้น นั่นทำให้การควบคุมลักษณะการตอบนั้นง่ายขึ้นเพราะ temperature คือตัวปรับอารมณ์ของระบบ
ค่าที่เหมาะขึ้นกับงานเช่นงานสกัดข้อมูลหรือโค้ดต้องใช้ temperature ต่ำและตัดความสุ่มออกไปให้มากที่สุดเพื่อลดความผิดพลาด ส่วนงานสร้างสรรค์ต้องใช้ตัวเลขที่ให้ความหลากหลายมากขึ้นแต่ยังคงอยู่ในขอบเขตของความสอดคล้อง ซึ่งเป็นที่ที่ temperature ได้แสดงบทบาท
### สูตร: temperature เปลี่ยนรูปความน่าจะเป็น

p(token) ∝ exp(logit / T)   (T ต่ำ → หัวแหลม deterministic, T สูง → แบน/สุ่ม)

> T→0 เท่ากับ greedy (เลือกสูงสุดเสมอ) ส่วน T→∞ เท่ากับสุ่มแบบ uniform

## top-p, top-k และความสัมพันธ์ของการสุ่ม

นอกจาก temperature แล้ว top-p เป็นการหยุดสะสมความน่าจะเป็นเมื่อผลรวมเกิน p แล้วยกกลุ่มนั้นมารวมแล้วสุ่มในกลุ่มนั้น ส่วน top-k จำกัดการเลือกลงจากอันดับสูงสุดเพียง k ตัวแรกของ vocab แนวคิดทั้งคู่เป็นการจำกัดความกว้างของการสุ่มที่ต้องทำงานพร้อม temperature
ทั้งสามอย่าง temperature, top-p, top-k คือตัวควบคุมการสุ่มแต่มีมิติต่างกัน ทำให้ชิ้นส่วนการควบคุมครอบคลุมได้หลายด้าน การเรียกใช้ทั้งหมดต้องจัดให้อยู่ใน service เดียวกันและทดสอบไม่ให้ซ้อนกันจนเกินไปเพราะจะกลายเป็น noise ที่คุมไม่ได้
สำหรับงานวิจัยที่ต้องการเริ่มจากการรันซ้ำแบบเดียวกัน การตั้งค่าต่าง ๆ เหล่านี้ต้องกำหนดให้ชัดเจนและทดสอบซ้ำเพื่อความเสถียร ในทางกลับกันในทาง product การเลือกใช้ค่าที่เหมาะกับงานจะมีผลมากกว่าการตามค่าที่สูงที่สุดใน literature

## context window และ "ความยาวที่ใช้ได้จริง"

Context window คือจำนวน token สูงสุดที่ใส่เข้าไปในครั้งเดียวโดยรวม input และ output ไว้ด้วยกัน ยิ่งโมเดลใหญ่ขึ้น context window ก็ขยายตามและทำให้ AI เข้าใจงานข้ามเอกสารได้มากขึ้น แต่อย่างไรก็ตามขนาดที่ใช้งานได้จริงมักน้อยกว่าตัวเลขที่โฆษณาไว้มาก
สาเหตุหลักมาจาก attention sink จาก KV cache และการเน้น primacy ของช่วงแรกของ context และต้องการการสังเคราะห์ที่กระจัดกระจาย ความยากของความยาวที่เกินง่ายนำไปสู่การลดประสิทธิภาพและความแม่นยำในตอนท้ายของ context หนัก
แนวทางที่ใช้ได้จริงคือการตัด context ให้เหลือเฉพาะส่วนที่เกี่ยวข้องกับงานและใช้ retrieval เพื่อดึงเฉพาะสิ่งที่จำเป็น จากหน้างานจริงต้องทดสอบกับข้อความที่ต้องอ้างความสัมพันธ์ยาว ๆ ก่อนที่จะสรุปว่าโมเดลใช้ context window ได้เต็มที่หรือไม่

## ทำไมบางโมเดล "ทำตามคำสั่ง" เก่ง บางตัวไม่

โมเดล base model ที่ pretrain อย่างเดียวจะเก่งเรื่องการต่อข้อความตามรูปแบบแต่ไม่ได้เก่งเรื่องการทำตามคำสั่งหรือการตอบเฉพาะรูปแบบที่ถูกต้องการ การทำตามคำสั่งต้องผ่านขั้นตอนการฝึกที่เรียกว่า instruction tuning และ preference alignment ซึ่งเป็นสิ่งที่ทำให้โมเดลอย่าง ChatGPT ต่างจาก base model เดิมมาก
Instruction tuning ใช้ข้อมูลที่คนเขียนตัวอย่าง prompt และ completion ที่มีคุณภาพเพื่อฝึกระบบให้ตอบตรงกับที่สั่ง ส่วน preference alignment ใช้การเปรียบเทียบระหว่างคำตอบแต่ละชุดเพื่อฝึกระบบให้เลือกคำตอบที่คนชอบมากกว่า กระบวนการเหล่านี้สร้างเลเยอร์ของความเข้าใจในคำสั่งที่เกินกว่า pretraining
เมื่อใช้งานจริงเราต้องเลือกใช้โมเดลให้ตรงกับหน้าที่ที่มันเคยถูกฝึกมาอย่างเป็นธรรมชาติ และอย่าลืมตรวจสอบการตอบของแต่ละโมเดลกับข้อมูลที่คุณใช้จริง เพราะจุดนี้ทำให้ความต่างระหว่างโมเดลเดียวกันที่มี data ลับของ SFT ต่างกันได้

## hallucination, confidence และ verification

Hallucination คือโมเดลตอบข้อความหรือตัวเลขที่ไม่สอดคล้องกับความเป็นจริงโดยอาศัยความคิดเชิงรูปแบบเป็นหลัก มันพร้อมที่จะตอบอย่างมั่นใจแม้ข้อมูลที่อ้างไม่มีจริงเพราะระบบไม่ได้ถูกฝึกให้ระแวดระวังในเรื่องความเข้าใจจากหลักฐาน แต่ถูกฝึกให้สร้างความน่าจะเป็นในการทำนาย token ที่ดูธรรมชาติ
ความมั่นใจที่สูงของโมเดลไม่ได้แปลว่าคำตอบนั้นถูกต้องเสมอไป เพราะโมเดลไม่มีกลไกที่รู้ว่าคำตอบที่ให้นั้นมีความเชื่อถือหรือไม่ ทำให้การตอบที่ดูมั่นใจแต่ผิดกลายเป็นเรื่องที่ผู้ใช้ยอมรับได้ง่าย นี่คือจุดที่หากไม่เสริมด้วยVerification จะกลายเป็นอันตรายอย่างมาก
ระบบอาชีพต้องเพิ่มชั้นการตรวจสอบจากการดึงข้อมูลจริง การดึงข้อมูลจากเอกสารมาอ้างและตรวจสอบว่าคำตอบมีหลักฐานรองรับ การใช้ RAG และ citation จึงเสริมความน่าเชื่อถือของโมเดลโดยการเปลี่ยนสิ่งที่โมเดลทำนายไป บนเป็นการตอบจากการดึงข้อมูลที่มีหลักฐานเปรียบเสมือนการเสริมกำแพงความน่าเชื่อถือให้คำตอบ

## ระยะทางตัวไหนใช้ตอนไหน

Cosine similarity วัดมุมระหว่างเวกเตอร์สองเส้นโดยไม่สนใจขนาดของมัน เมื่อ embedding ถูก normalize ไว้แล้วผลของ cosine จะเท่ากับ dot product ซึ่งบ่งบอกความคล้ายเชิงความหมายได้ดี ส่วน Euclidean distance วัดระยะทางที่รวมขนาดของเวกเตอร์ไปด้วยซึ่งอาจเหมาะกับงานที่ขนาดมีความหมายจริง เช่น ศัพท์เฉพาะบางประเภท
การเลือก metric จึงต้องเลือกให้เหมาะสมกับข้อมูลจริงและการตั้งค่าว่า embedding มีการ normalize ไว้หรือไม่ ซึ่งจะเปลี่ยนผลลัพธ์ของการค้นคืนได้มาก ค่า 1 หมายถึงทิศทางเดียวกันและใกล้เคียงกันมากแต่ไม่มีหมายความว่าผลรวมสองเส้นนั้นใกล้กันเสมอไปในเชิงขนาดความยาว
vector database จะมีการตั้ง metric อยู่ก่อนว่าต้องใช้แบบใด เมื่อคุณเลือก embedding model ที่ normalize หรือไม่ normalize ตัว metric ที่เลือกต้องสอดคล้องกันกับวิธีการคำนวณที่ใช้ในโมเดล เพื่อให้ index ของระบบค้นคืนเกิดผลที่ตรงกับสมการที่ใช้ในโมเดลจริง
### สูตร: Cosine similarity

cos(θ) = (a·b) / (||a|| ||b||)

> ค่า 1 = ทิศเดียวกัน (คล้าย), 0 = ตั้งฉาก (ไม่เกี่ยว), -1 = ตรงข้าม

## ANN และ HNSW: ดึงใกล้ไม่ต้องไล่ทั้งหมด

การค้นแบบ exact ต้องคำนวณความคล้ายกับทุก vector ซึ่งช้ามากเมื่อจำนวน vector มีหลายล้านหน่วย ANN จึงแก้ปัญหานี้ด้วยการยอมเสียความแม่นยำบางส่วนเพื่อความเร็ว ทำให้ระบบนำความใกล้เคียงมาสู่ผลลัพธ์สุดท้ายได้อย่างถูกต้อง
HNSW สร้าง multi-layer graph ซึ่งชั้นบนเชื่อมแบบกระโดดไกลแล้วชั้นล่างค่อยเชื่อมแบบกระโดดใกล้ วิธีนี้ทำให้ได้ recall สูงและความเร็วสูงแม้จะมี graph ใหญ่ เมื่อทำการค้นจะได้ความใกล้เคียงภายในเวลาสั้นและได้ข้อเสนอแนะในการปรับขนาดของ efSearch กับ M ได้
พารามิเตอร์ที่ต้องรู้เสมอคือ efConstruction, efSearch และ M ซึ่งกำหนดกำลังของ index ว่าชัดเจนแค่ไหน การไล่แบบทั้งหมดแม้เร็วกว่าแต่ก็ช้ากว่ามาก การออกแบบจึงเป็นการแลกเปลี่ยนระหว่างความแม่นยำและความเร็วและการจัดการ RAM อย่างเหมาะกับงาน

## BM25 และ hybrid search: รวมคำกับความหมาย

BM25 เป็น keyword retrieval ที่ match คำที่ต้องการอย่างตรงไปตรงมาเนื่องจากอาศัยความถี่ของคำในเอกสารและความถี่ของคำที่เห็นทั่วไป วิธีนี้เก่งเรื่องคำหายากและศัพท์เฉพาะที่ embedding อาจกลบไป แต่ก็ไม่มีความเข้าใจในเรื่องความหมายของคำ
Dense retrieval เก่งเรื่องความหมาย เพราะรู้ว่าคำที่แตกต่างกันสามารถมีความหมายเดียวกันได้และการค้นหาโดยใช้คำเดียวกันอย่างตรงไปตรงมาอาจไม่เจอสิ่งที่อยู่ในบริบทเดียวกัน แต่นั่นไม่อาจจับคำสำคัญที่หายากที่สุดได้เช่นกัน
hybrid search จึงรวมทั้งสองวิธีเข้าด้วยกันเพื่อได้ขีดความสามารถที่ดีกว่า เมื่อรวมแล้ว candidate ที่ถูกเลือกมักจะครบถ้วนและมีความหลากหลายมากขึ้น นั่นคือเหตุผลที่ hybrid เก่งกว่าใช้วิธีเดียวอย่างชัดเจนในงานจริง และไม่ต้องพึ่ง embedding อย่างเดียวเสมอไป

## reranking และ cross-encoder

reranking คือการให้โมเดลที่ดีกว่าการทำ embedding อีกรอบเพื่อจัดลำดับคำตอบให้แม่นยำ โดยเปรียบเทียบ query กับ doc เต็มทั้งประโยคมากกว่าการเปรียบเทียบ vector วิธีนี้ทำได้แม่นกว่า modular reranker ที่มากกว่า HNSW และ BM25 มาก
cross-encoder เปรียบเทียบ query กับ doc เต็มประโยคในครั้งเดียวและจะทำได้แม่นกว่าโมเดลที่สร้าง embedding ออกมาโดยตรง ข้อแลกเปลี่ยนคือการคำนวณทั่วทั้งประโยคจะต้องใช้เวลาและทรัพยากรมากกว่า embedding
โดยรวมแล้ว cross-encoder นำเฉพาะหลังจากเราได้ candidate ไว้แล้วจำนวนหนึ่งเพื่อทำการ rerank ท้ายก่อนส่งเข้า context การเอา candidate 20 ถึง 50 อันแล้ว rerank เหลือ 5 ถึง 8 อันเป็นการทำงานที่ดีที่สุดสำหรับงานส่วนใหญ่ในชีวิตจริง

## วัดคุณภาพ retrieval ก่อนเชื่อตัวเลข

Retrieval metrics หลักคือ recall@k ซึ่งแสดงว่าของที่ถูกอยู่ใน k อันแรกหรือไม่ และ hit rate ที่ threshold ที่ช่วยให้คำนวณได้ว่าของที่ต้องการจะเจอได้มากน้อยแค่ไหน แต่ metric พวกนี้อย่างเดียวไม่บอกเราว่างานในที่สุดจะใช้ได้หรือไม่ ถ้าผลตอบไม่ได้แสดงไปจึงไม่ต้องไปวัดต่อ จากนั้นจึงต้องสร้าง golden set ที่วัดได้ส่วนหนึ่งของคำถามแยกกัน
golden set คือชุด query 30 ถึง 50 ข้อจากผู้ใช้จริงและเชื่อมกับเอกสารที่มีความหมาย ซึ่งมั่นใจว่า subset ที่มีผลลัพธ์ตรงกับความต้องการของผู้ใช้จะถูกวัดได้อย่างครบถ้วน
การปรับ threshold บนชุดคำตอบนี้ทำให้เรารู้ได้ว่าค่าที่แสดงจะดีกว่าในที่สุด การไม่วัด retrieval จะทำให้เรา optimizes ตามความรู้สึกและการวัดจะไม่แม่นยำโดยตรงที่จะดีขึ้นเพียงเพราะการใช้ค่าที่ใกล้เคียงกัน

## vector store ops: indexing, update และการลบ

บัญชีการจัดเก็บข้อมูลต้องมี indexing ที่ถูกต้องและการจัดการอัปเดตที่ทำให้ไม่มีข้อมูลซ้ำซ้อนเวลาค้น การเพิ่ม vector ต้องแนบ metadata ที่จำเป็นและต้องมีการสร้าง index ใหม่เพื่อรองรับการค้นหา การอัปเดตจะทำให้ข้อมูลเก่าค้างได้ถ้าไม่ลบ vector เดิมออก
การลบข้อมูลต้องทำอย่างครบถ้วนเพราะถ้า vector เก่าก่อนยังคงอยู่หลังอัปเดต ความใกล้เคียงอาจย้อนกลับไปหาข้อมูลใหม่ได้และการค้นคืนจะไม่แม่นยำอีกต่อไป การจัดการ pipeline จึงสำคัญมากและเป็นงานที่ต้องทำให้สมบูรณ์ครบทุกฝ่าย
ขั้นตอนที่ออกแบบไว้ให้ถูกต้องจะช่วยลดความผิดพลาดและทำให้ vector store มีความเสถียรอยู่เสมอ การควบคุมเหล่านี้มีผลที่สำคัญต่อคุณภาพของงานและต้องทำงานพร้อมกับ embedding และ retrieval อย่างสอดคล้องกัน

## จาก perceptron ตัวเดียวสู่ชั้นหลายชั้น

Perceptron รับเวกเตอร์ input, คูณ weight, รวมกับ bias แล้วเปรียบเทียบผลรวมนั้นกับค่าที่กำหนดไว้ ถ้าผลรวมเกินเกณฑ์มันจะตอบว่า 1 ถ้าไม่เกินมันจะตอบว่า 0 ภาพของมันคือการลากเส้นตรงเส้นหนึ่งเพื่อแยกข้อมูลออกเป็นสองฝั่ง การตัดสินใจจึงขึ้นกับเส้นเส้นนั้นเพียงเส้นเดียวและเปลี่ยนรูปไม่ได้
ต่อมาเมื่อนักวิจัยพบว่า perceptron ชั้นเดียวแก้ปัญหาอย่าง XOR ไม่ได้เพราะฟังก์ชันต้องพับซ้อนในลักษณะที่เส้นตรงเส้นเดียวทำไม่ได้ พวกเขาจึงเพิ่มชั้นที่อยู่ระหว่าง input กับ output เรียกว่า hidden layer ชั้นเหล่านี้ไม่ได้ทำหน้าที่ตัดสินใจสุดท้าย แต่ทำหน้าที่แปลงข้อมูลให้อยู่ในรูปที่ชั้นถัดไปแยกต่อได้
การซ้อนชั้นทำให้เครือข่ายจับฟังก์ชันซับซ้อนขึ้นเรื่อย ๆ โดยชั้นแรกมักจับความแตกต่างง่าย ๆ อย่างเช่นขอบของภาพ ชั้นถัดไปรวมขอบเหล่านั้นเป็นรูปทรง และชั้นสุดท้ายตัดสินว่าเป็นวัตถุประเภทใด ความลึกจึงหมายถึงลำดับชั้นที่ซ้อนกัน แต่ละชั้นแปลงข้อมูลทีละขั้น ไม่ใช่การคำนวณแยกกัน
ข้อได้เปรียบของ neural network เหนือโมเดลก้าวกระโดดอย่างต้นไม้ตัดสินใจคือน้ำหนักทุกตัวเปลี่ยนค่าต่อเนื่องได้โดยไม่มีรอยต่อ โมเดลจึงถูกปรับด้วย gradient ได้อย่างราบรื่นและหาค่าที่ดีกว่าได้ทีละขั้น ความต่อเนื่องนี้เป็นรากฐานของอัลกอริทึมเทรนสมัยใหม่ทั้งหมด
### สูตร: การคำนวณของ perceptron ตัวเดียว

z = w·x + b   ·   y = activation(z)   (w = weight, b = bias, x = input, z = ผลรวมก่อน activation)

> Perceptron หนึ่งตัวคูณ input ด้วย weight รวมเป็น z แล้วผ่าน activation เพื่อให้ค่า y ส่วน hidden layer คือการทำแบบเดียวกันนี้ซ้ำกับหลายหน่วยพร้อมกัน

## activation: แหล่งของความไม่เป็นเส้นตรง

ถ้าไม่มี activation การซ้อนชั้นหลายสิบชั้นจะเท่ากับชั้นเดียวเพราะการคูณและการบวกเชิงเส้นแม้ซ้อนกันกี่ครั้งก็ยังได้เส้นตรง เข้าใจจุดนี้แล้วจะเห็นว่า activation ไม่ใช่ฟังก์ชันประดับ แต่เป็นตัวทำให้เครือข่ายจับความสัมพันธ์ที่ไม่เป็นเส้นตรงได้ โมเดลจึงปรับตามรูปโค้งของข้อมูลได้ ไม่ใช่เพียงเส้นตรงที่ผ่านกลางข้อมูล
ReLU ถูกใช้เป็นค่าเริ่มต้นของ hidden layer ในงานส่วนใหญ่เพราะคำนวณง่ายและทำให้ gradient ไหลได้ดีเมื่อค่าเป็นบวก มันใช้สูตร max(0, x) คือตัดค่าลบให้เป็น 0 ส่วน sigmoid และ softmax เหมาะกับชั้นสุดท้ายของงานจำแนกประเภทเมื่อต้องการความน่าจะเป็น ส่วนงานถดถอยจะใช้ linear ในชั้นสุดท้ายเพราะต้องการค่าต่อเนื่องโดยตรง
sigmoid กับ tanh เคยนิยมมากแต่ไม่แนะนำสำหรับ hidden layer ลึกในวันนี้ เพราะเมื่อ input ใหญ่ค่าจะอิ่มตัวที่ค่าขอบ ทำให้ gradient ใกล้ศูนย์ ชั้นลึกจึงไม่ขยับ การเลือก activation จึงไม่ใช่แค่ว่าแบบไหนนิยม แต่ต้องดูว่า gradient ไหลได้หรือไม่ในโครงสร้างที่เราออกแบบ
**ตัวอย่าง — ทำไมต้องมี hidden layer**

AND แบ่งด้วยเส้นเดียวได้ (y = x1 AND x2) แต่ XOR (คำตอบจริงเมื่อต่างกัน) จุดทั้ง 4 วนกลับ แบ่งเส้นเดียวไม่ได้ — hidden layer ช่วย "บิดพื้นที่" ให้เข้าถึงคำตอบได้

## backpropagation: chain rule ที่วิ่งย้อนกลับ

Backpropagation คือการไล่ derivative ของฟังก์ชันพันกันย้อนกลับจากปลายไปยังต้น มันเริ่มจากคำนวณค่าการทำนายและความผิดก่อนจากนั้นถามว่าถ้าเราขยับค่าในชั้นสุดท้ายนิดหนึ่ง loss จะเปลี่ยนอย่างไร และถ้าขยับค่าก่อนหน้านั้นอีก loss จะเปลี่ยนอย่างไร การถามแบบต่อกันนี้ต่อเนื่องไปถึง weight ตัวแรกสุด
ในทางปฏิบัติเราไม่ได้คำนวณด้วยมือ แต่คำนวณให้ทั้งโครงข่ายเห็นภาพการเชื่อมต่อเป็นลำดับคำนวณ ไลบรารีอย่าง PyTorch จึงคำนวณ gradient ของ parameter ทุกตัวหลังคำนวณ loss หนึ่งรอบ ความเข้าใจว่าการคำนวณนี้อาศัย chain rule ทำให้เราอ่านข้อผิดพลาดได้อย่างมีเหตุผล เช่น gradient ที่หายไปหรือระเบิดไป
ข้อควรระวังที่พบเสมอในการเทรนคือต้องล้าง gradient เก่าออกก่อนแต่ละรอบ เพราะถ้าไม่ล้างระบบจะสะสม gradient ของหลายรอบเข้าด้วยกัน เปรียบเหมือนการเดินลงเขาด้วยความจำของก้าวก่อนที่สะสมขึ้นเรื่อย ๆ แทนที่จะมองเฉพาะทิศที่ตำแหน่งปัจจุบันชี้ การล้าง gradient จึงเป็นขั้นตอนเล็ก ๆ ที่เปลี่ยนผลลัพธ์อย่างมาก
```pytorch
for xb, yb in loader:
    optimizer.zero_grad()   # สำคัญ: ล้าง gradient เดิม
    loss = criterion(model(xb), yb)
    loss.backward()         # คำนวณ gradient ทั้งวงจร
    optimizer.step()        # ขยับ weight ตาม gradient
```
![Input, two hidden, and output layers with forward arrows computing z equals W x plus b and backward arrows returning gradients via the chain rule; vanishing gradient note](/diagrams/neural-network.svg)

*Neural network: forward and backward — Forward คำนวณ z = Wx + b → σ → ŷ → loss; Backward คูณ Jacobian ย้อนกลับตาม chain rule — ผลคูณของค่าเล็กหลายชั้นคือ vanishing gradient*

## weight init, optimizer และ normalization: แก้ปัญหา "เทรนไม่ขึ้น"

การเริ่ม weight มีผลต่อเนื่องมากกว่าที่หลายคนคิด เพราะ weight ในชั้นแรกมีผลต่อค่าทุกชั้นที่ตามมาโดยการคูณทบกัน ถ้าเริ่มต้นใหญ่ไปค่าจะพุ่งจนควบคุมไม่ได้ ถ้าเริ่มต้นเล็กไป gradient จะหายจนไม่เรียนรู้ ระบบจึงต้องเริ่มต้นที่สเกลพอเหมาะเพื่อให้สัญญาณไหลผ่านไปกลับได้อย่างไม่บิดเบี้ยว
วิธีเริ่มต้นมาตรฐานปรับสเกลตามจำนวนเส้นที่เชื่อมเข้าชั้นหนึ่ง ๆ เช่น Xavier หรือ Glorot เหมาะกับ sigmoid และ tanh ส่วน Kaiming หรือ He เหมาะกับ ReLU เพราะฟังก์ชันนี้ตัดครึ่งค่าลบไปทำให้สเกลกระจายเปลี่ยน หลักการเดียวกันคือรักษาระยะกระจายของสัญญาณให้คงที่เมื่อผ่านตั้งแต่ชั้นแรกถึงชั้นสุดท้าย
Optimizer แบบ SGD ดั้งเดิมขยับตาม gradient เพียงอย่างเดียว ส่วน Adam เพิ่ม momentum เพื่อไม่ให้สั่นไปมาตามเสียงของข้อมูล และปรับ learning rate แยกกันให้ parameter แต่ละตัว วิธีนี้เทรนเร็วและทนต่อ hyperparameter ที่ยังไม่สมบูรณ์ แต่ไม่ใช่ทางชนะเสมอไป เพราะงานบางประเภทต้องการการตัดสินใจที่คมชัดกว่า ซึ่ง SGD ควบคู่ momentum กับตารางลด learning rate อาจทำได้ดีกว่า
Batch Normalization กับ Layer Normalization ไม่ได้แก้ทุกปัญหาในครั้งเดียว แต่ทำให้สัญญาณมีขนาดพึ่งพาได้น้อยลงและทำให้ภาพ loss เรียบขึ้นจึงสามารถใช้ learning rate สูงขึ้นได้ ผลพลอยได้คือโมเดลพึ่งพาการเริ่มต้น weight น้อยลงและเทรนได้เร็วขึ้น นี่คือ trade-off ระหว่างความซับซ้อนของโครงสร้างกับความสบายในการเทรน
### สูตร: การปรับ weight ด้วย gradient descent

θ ← θ − η · ∇L(θ)   (θ = weight หรือพารามิเตอร์, η = learning rate, ∇L = gradient ของ loss)

> เราขยับ weight ไปทิศตรงข้ามกับทิศที่ gradient ชี้เพราะ gradient ชี้ไปทิศที่ loss เพิ่ม การคูณด้วย learning rate ควบคุมขนาดก้าวว่าเล็กหรือใหญ่

## ความลึก: เมื่อ deeper ไม่ได้แปลว่าดีกว่าเสมอ

การเพิ่มชั้นทำให้เครือข่ายสร้างลำดับการจับ feature ได้ละเอียดขึ้น แต่เพิ่มความยากในการเทรนพร้อมกัน เพราะ gradient ต้องไหลผ่านชั้นมากขึ้นและต้องปรับให้สมดุลทุกชั้นพร้อมกัน นี่คือ trade-off หลักของความลึกคือกำลังแสดงผลที่เพิ่มมากับต้นทุนในการฝึกและคำนวณที่สูงขึ้นเรื่อย ๆ เมื่อมีชั้นมากเกินวรรคฝึก อาจเสียเวลาไปกับการปรับที่ไม่จำเป็นแทนที่จะได้ผลดีที่ใช้ได้จริง
การออกแบบเครือข่ายที่ดีจึงต้องเริ่มจากข้อมูลและโจทย์ก่อน ไม่ใช่เริ่มจากความคิดว่าโมเดลยิ่งใหญ่ยิ่งดี ข้อมูลน้อยและซับซ้อนไม่มากอาจใช้โครงสร้างเล็กกว่าได้ดีและเข้าใจง่ายกว่าเมื่อเทรน การเริ่มจากโมเดลเล็กแล้วค่อยขยายทำให้เรารู้ได้ว่าส่วนใดกำลังทำงาน และส่วนใดกำลังถ่วงงาน
เครื่องมืออย่าง dropout ช่วยลดการพึ่งพาเฉพาะหน่วยใดหน่วยหนึ่งด้วยการปิดหน่วยสุ่มบางส่วนในรอบเทรน ส่วน weight decay ลงโทษ weight ที่มีค่ามากเพื่อไม่ให้พึ่งพาความจำของข้อมูลเดิมมากเกิน จุดมุ่งหมายคือบังคับให้โมเดลเรียนรู้กฎที่กว้างขวางกว่าการท่องจำข้อมูลเฉพาะกลุ่ม
> [!SYMMETRY]
> ถ้า weight ทุกตัวในชั้นเริ่มเท่ากัน หน่วยในชั้นนั้นจะได้ gradient เท่ากันและขยับเป็นค่าเดียวกันตลอดไป โมเดลจึงทำหน้าที่เหมือนมีหน่วยเดียว การเริ่มต้นแบบสุ่มเล็ก ๆ จึงจำเป็นเพื่อแยกบทบาทของหน่วยแต่ละตัว

## วินิจฉัยเทรนไม่ดีเป็นลำดับ

เมื่อผลเทรนไม่ดีให้ตรวจที่ละขั้น โดยเริ่มจากโค้ดและข้อมูลเพราะจุดนี้มักผิดมากกว่าที่คิด เช่น การแบ่งคลาสผิด การไม่ normalize ข้อมูล input หรือการลืมตั้งค่า loss ให้ตรงกับงาน ควรทดสอบกับตัวอย่างเดียวว่าอาจทำให้ loss ลดลงตามที่คาดหรือไม่ ถ้างานนี้ยังไม่ผ่านอย่าเพิ่งไปยุ่งกับโครงสร้างโมเดล
ถ้าข้อมูลและโค้ดถูกต้องแล้วแต่ loss ไม่ลด ให้ไล่ดู learning rate และ optimizer เป็นอันดับต่อไป learning rate เล็กไปจะช้าเกินไปแต่ใหญ่ไปจะสั่นและห่างจากคำตอบ ส่วนค่า gradient หากหายไปหรือระเบิดจะมีสัญญาณว่า gradient มีปัญหาต้องตรวจสอบ init กับ normalization ประกอบกัน
ถ้า train loss ลดแต่ validation loss ไม่ลดคืออาการของ overfitting ต้องเพิ่มข้อมูลที่ดีกว่าเดิม ใช้ regularization และลดความซับซ้อน อย่าดูแค่ตัวเลขสุดท้าย แต่ดูกราฟการเปลี่ยนแปลงว่าเส้น train กับ validation แยกจากกันที่จุดใด เพื่อเลือกจุดหยุดที่สมเหตุสมผล
> [!RULES OF THUMB]
> ถ้าเทรนไม่ขึ้น: (1) ตรวจโค้ด-ข้อมูล ถูกต้องสุด (2) ทำให้ example เดียว loss ได้ตามที่คาด (3) แล้วค่อยไล่ lr/optimizer อย่าเริ่มที่สถาปัตยกรรมใหม่
